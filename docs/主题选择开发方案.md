# 主题选择开发方案

状态：本地实现与自动化验证已完成，待真机专项验收。确认及实现日期：2026-09-10。

## 目标与默认值

为读者提供四种配色风格，并允许独立选择显示模式。主题偏好保存在本机，不归账号，退出或切换账号不清除。

- 配色风格：墨青绿、石板蓝、暖琥珀、莓果玫瑰。
- 显示模式：跟随系统、浅色、深色。
- 默认值：**石板蓝 + 跟随系统**。
- 未选择、读取失败或遇到未知持久化值时，回退默认值。

深色不是第五种配色。配色和明暗作为两个独立维度保存；切换明暗不丢失当前配色，切回时仍保持读者上次选择。

## 视觉约束

第一版种子色如下，完整实现必须由种子色生成或人工补齐全部 Material 3 `ColorScheme` 角色，并逐项验证；不能只覆盖 `primary`、`surfaceVariant` 等少数角色，以免组件继续继承默认紫色。

| 配色 | 浅色 primary | 深色 primary | 定位 |
|---|---:|---:|---|
| 墨青绿 | `#006B5B` | `#82D5C2` | 冷静、技术、自然 |
| 石板蓝 | `#315F84` | `#9CCAFA` | 稳妥、专业，默认 |
| 暖琥珀 | `#795900` | `#EFC15C` | 纸张、编辑感 |
| 莓果玫瑰 | `#8A3F62` | `#FFAFCE` | 柔和、成熟、亲近 |

共同规则：

- 阅读页面和普通文章卡片使用中性背景与表面，品牌色只用于链接、按钮、选中和焦点状态。
- “每日一问”与普通文章使用同类中性表面，只用主色侧边标记和标题色建立层级，不使用大面积异色背景。
- 四套深色方案共享低亮度中性背景、表面、文字和轮廓体系，只替换主色及其容器色。
- 文本与背景对比度：普通文字至少 4.5:1，大号文字至少 3:1；状态不能只靠颜色表达。
- 为每套配色补齐 `secondary`、`tertiary`、`error`、`outline*`、`inverse*`、`surfaceContainer*` 和 fixed color 等当前 Material 3 角色。
- 动态取色不纳入第一版，避免系统壁纸覆盖读者明确选择的配色。

## 交互方案

入口放在“我的 → 外观与主题”。

- “配色风格”使用 2 × 2 预览项，显示名称、代表色和明确选中标记。
- “显示模式”提供“跟随系统 / 浅色 / 深色”三个文字选项，默认跟随系统。
- 点击后即时预览，持久化成功后成为最终状态；失败时恢复之前选择并给出非敏感错误提示。
- 颜色不是唯一识别手段；选项有文字、选中图标和无障碍状态描述。
- 触摸目标至少 48dp，并验证大字体和屏幕阅读器下的布局及语义。

如果视觉稿需要把“深色”画成第五张卡片，该卡片只作为显示模式快捷入口，内部仍保留“当前配色 + 深色”的两个字段，不能存成第五个互斥主题。

## 数据与架构

请求链路遵守 `Route/Screen → ViewModel → Repository → DataSource`：

```text
ProfileRoute / ProfileScreen
  → ProfileViewModel
  → ThemePreferencesRepository
  → Preferences DataStore

AppViewModel
  ← ThemePreferencesRepository 的 Flow
  → WanTheme(palette, resolvedDark)
  → 全局 Compose 内容
```

模块职责：

- `core:designsystem`：只保存视觉枚举、完整浅深色 `ColorScheme` 和解析函数，不接触 DataStore、账号或 Feature。
- `core:data`：保存 UI 无关的主题偏好模型、DataStore DataSource、Repository 契约与实现，不导入 Compose。
- `app`：收集全局主题状态，将持久化偏好映射到 designsystem，并组装根主题和 Feature。
- `feature:profile`：Route 获取 ViewModel，Screen 只接收状态和事件，不直接访问 DataStore。

不创建单独的空 `core:datastore` 模块。当前规模下将偏好数据源放入 `core:data`，以后出现多个独立设置域且职责明显膨胀时再评估拆分。

## 持久化契约

已采用 `androidx.datastore:datastore-preferences:1.2.1`，统一写入 Version Catalog，仅由 `core:data` 使用。

建议稳定键和值：

- `theme_palette`：`ink_teal`、`slate_blue`、`warm_amber`、`berry_rose`。
- `theme_mode`：`follow_system`、`light`、`dark`。

不得直接持久化 Kotlin enum 的 ordinal。将来重命名或删除值时显式映射；未知值回退 `slate_blue` 或 `follow_system`。读取 `IOException` 时回退默认并保留可观测失败信息，取消异常必须重抛；写入失败不能把未落盘选择宣称为已保存。

主题偏好属于本机非敏感设置，不随 Cookie 或账号清理。当前应用禁止系统备份，因此不承诺跨设备或重装恢复。

## 明暗解析与系统界面

`resolvedDark` 规则：

- `follow_system`：使用 `isSystemInDarkTheme()`。
- `light`：固定为 `false`。
- `dark`：固定为 `true`。

应用根节点只接收解析后的结果。主题切换时同步更新状态栏和导航栏图标明暗，确保 Edge-to-edge 背景上的图标对比正确。系统模式变化只应在 `follow_system` 下改变应用明暗；固定浅色或深色时不能被系统变化覆盖。

DataStore 首次读取是异步的。首帧先使用“石板蓝 + 跟随系统”；实机验证若出现明显闪烁，再评估 AndroidX SplashScreen 等待首次偏好加载，不能用阻塞主线程读取规避。

## WebView 与离线正文边界

主题选择首先保证原生 Compose 界面。在线第三方网页是否能暗色显示取决于页面是否支持 `prefers-color-scheme` 或允许 WebView 算法变暗，不能承诺所有站点一致。

- 在线 WebView 接入时单独验证页面自带暗色、算法变暗、明确禁用变暗和图片可读性。
- 不使用已废弃的 `setForceDark`；如需算法变暗，使用 AndroidX WebKit 的兼容能力并先检查 Feature 支持。
- 本项目自行生成的净化离线正文必须提供受控的浅深 CSS，不依赖第三方页面样式。
- 主题切换不得放宽 JavaScript、文件访问、TLS 或外部 scheme 安全边界。

## 实施顺序

1. 在 designsystem 建立四套浅色和对应深色 Token，完成完整角色与解析测试。
2. 在 `core:data` 加入 Preferences DataStore、偏好 Repository、默认值和异常处理测试。
3. 在 app 根节点接入主题状态，并同步系统栏图标。
4. 在 profile 增加主题选择 Route/Screen，完成即时预览、保存失败与无障碍状态。
5. 更新第一版验收清单并执行统一 Debug 验证；WebView 接入后补充网页暗色专项验证。

## 测试与验收

- 默认无数据时解析为“石板蓝 + 跟随系统”。
- 四种配色的浅色、深色共 8 组映射正确，所有组件不泄漏 Material 默认紫色。
- 跟随系统在系统浅色和深色下正确；固定模式不随系统切换。
- 快速连续选择以最后一次成功写入为准；进程重启后恢复。
- 未知值、读取失败、写入失败和取消传播行为明确。
- 状态栏、底部导航、卡片、弹窗、加载、空、失败和禁用状态均可读。
- 大字体、深色、触摸目标、屏幕阅读器语义和对比度通过设备验证。
- 本地最终执行：

```bash
./gradlew verifyArchitecture spotlessCheck :app:assembleDebug testDebugUnitTest lintDebug
```

当前实现已通过统一 Debug 验证和 35 个单元测试；设备显示、系统模式联动、大字体、屏幕阅读器、进程重启恢复及 Release 仍未验证，不能据此视为完成真机验收。

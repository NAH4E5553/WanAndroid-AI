## 模块图

- app → feature:home / topics / profile / article / auth，负责组装。
- feature → core:data / model / navigation / designsystem / ui，明确声明实际使用的依赖。
- core:data → core:network / database / model，业务转换、共享数据所有权和本机主题偏好持久化。
- core:network → core:model（如边界需要），DTO 保持在 network。
- core:database → Room，Entity 不泄漏到 UI。
- core:navigation → Navigation3 runtime + Serialization，只有路由和小型参数。
- core:ui → designsystem / model，不接触 Repository。
- core:designsystem → Compose，保存完整主题 Token，不依赖业务、数据或 Feature 模块。

不建立无实际用途的 common/util/datastore 空模块。主题偏好使用 `core:data` 内的 Preferences DataStore；会话实现进入下一阶段时再确定安全持久化最小边界，不得先持久化密码。
不额外引入 Domain 模块或用例层；多 Repository 业务协调实际需要时再引入。

## 构建决策

沿用来源已使用的 AGP 9.0.1、Kotlin 2.3.10、Gradle 9.3.1、Hilt 2.59.1、Navigation3 1.0.1、Room 2.8.4 和 Compose BOM 2026.02.00。

只有一个公开后端，第一版只保留 debug/release，不复制同地址的 dev/prod 组合。
应用身份放 app；通用插件不硬编码某个 App 的 applicationId 或后端地址。
Feature 插件只组合 Android/Compose/Hilt 和通用 UI 依赖，业务 Core 依赖显式声明。
不复制 Jetifier、ABI 限制、第三方 Manifest 占位或 origin/main ratchet。

## 数据协议

API：https://wanandroid.com/；说明：https://wanandroid.com/blog/show/2。
WanResponse 必须存在 errorCode，0 成功，-1001 会话失效，其他非零业务错误。
DTO 字段宽容但关键错误码不默认成功；Repository 转换为领域 Article/PageResult。
文章列表与查询从 0 开始；问答从 1 开始。用响应 over 和请求快照生成 nextPage，不按“少于 pageSize”推断末页。
分类展示平铺一级和二级，保留 parentId。父类查询能力必须实测，不偷偷把父类 ID 映射到第一个子类。

## 状态边界

- UI 局部：滚动位置、搜索输入、轮播索引。
- ViewModel：请求标识、加载状态、当前查询/分类、页面列表。
- Repository：会话、账号维度的收藏、数据库数据协调。
- 服务端：会话有效性、收藏最终事实。
- 本机：阅读历史、离线正文和主题偏好，退出不删除；历史与离线内容可以分别清理，主题偏好在应用数据清除或卸载前保留。

## 数据库设计（第一版契约）

history：url 为本机去重键，articleId 可空、title、lastReadAt；重复阅读覆盖时间，不表示已读完。
offline_articles：url 为键，title、sanitizedHtml 可空、status、cachedAt、byteCount；与 history 无级联删除。
正文只在打开离线文章时读取；历史和缓存列表分页，不整表携带 HTML。
初步资源预算：单篇正文 1 MiB，总正文 50 MiB，单任务 20 秒，并发 1；超限明确失败，不静默截断。
按最近访问淘汰缓存；成功状态和正文事务提交；异常中断的任务下次启动可重试。
离线优先保证正文，不宣称网页图片/视频/交互已完整下载。
这些阈值属于初始安全限制，真实内容验证后调整，并记录依据。
